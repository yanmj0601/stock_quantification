第 2 步：页内信息层级怎么排

重点不是多漂亮，而是每一页打开后都能立刻知道“先看什么、再做什么”。

总览页
1. 页面定位
今天发生了什么
一句话摘要 + 跳转建议
2. 最近运行
2. 研究结论
2. 系统健康
2. 风险提醒
3. 最新结果摘要列表
3. 下一步去哪里
4. 少量快捷动作，不放复杂表单

总览页层级

先给结论，再给状态，再给去向。首页不允许出现长表单、大表格、深度分析块。

研究工作台
1. 页面定位
运行、回测、实验都在这里做
操作页可以重，但只能重在同一类任务上
2. 最近一次运行状态
2. 最近一次回测状态
2. 当前默认配置
3. 策略运行表单
3. 因子回测表单
4. 最近执行结果
4. 参数提示 / 说明

研究工作台层级

把“操作”和“最新执行反馈”放在一起，但不混入历史归档、模拟盘流水、系统日志。

研究结果页
1. 页面定位
浏览、筛选、对比结果
研究结果和运行结果分区展示，但进入同一结果中心
2. 筛选条：结果分组 / 类型 / 市场 / 时间
3. 结果列表 / 紧凑卡片表
3. 选中结果详情面板
4. 工件下载与跳转

研究结果页层级

先筛选，再看列表，再看详情。结果页不承担运行表单和系统控制按钮。

这套层级的好处

  • 用户打开任意页面时，第一屏就能知道这个页面值不值得继续停留。
  • 首页不再沦为“所有功能的堆场”，研究和结果也不会互相干扰。
  • 顶部状态栏终于只做状态，不再和左侧导航抢职责。

需要注意的点

  • 研究工作台会成为最重的页面，需要做明显的表单分区。
  • 结果页必须把“研究结果”和“运行结果”清楚分组，否则还是会混。
  • 总览页必须克制，不能把后续新功能又往首页塞回去。
