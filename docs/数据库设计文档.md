# 数据库设计文档

> 本文描述当前代码，不代表计划功能。技术和部署全貌见 [系统架构](系统架构设计文档.md)，业务语义见 [PRD](产品需求文档.md)。初始化脚本：[sql/初始化.sql](sql/初始化.sql)。

## 1. 数据库与存储约定

运行时唯一数据库是 PostgreSQL，使用 psycopg2；`Store` 是 `PostgreSQLStore` 的别名。未配置 `EVOQUANT_DB_URL` 时连接本机 `postgresql://localhost:5432/evoquant`；生产及容器显式配置连接参数。SQLite、MySQL、Redis 均不是当前运行时依赖。保留的 SQLite 方言适配器用于转换占位符和旧查询，不表示支持 SQLite 数据库。

当前共 16 张表。时间使用 `TEXT` 保存 ISO 8601（应用通常使用 UTC）；日期保存 `YYYY-MM-DD`。JSON 使用 `TEXT` 加应用层序列化，未使用 JSONB。布尔值使用整数 0/1。金额和数量使用双精度浮点数，尚未使用定点 DECIMAL。除表中标明可空的字段外，普通字段均为 NOT NULL；主键也隐含非空。数据库未声明外键、枚举或 CHECK 约束，关联和状态校验由服务实现。

每个 `store.connection()` 上下文独立连接：正常退出提交，异常回滚，最后关闭。没有 ORM 或连接池。`initialize()` 创建 11 张基础表；`PaperTradingService` 创建 4 张模拟交易表；`RiskService` 创建风险表。应用完整初始化后具备下列全部表。

## 3. 逻辑关系和索引

- `strategies.id` 与草稿 `strategy_id`、审计 `entity_id` 按业务关联。
- `market_sync_jobs.id` → `market_quality_reports.sync_job_id`。
- `signal_scans.id` → `signal_results.scan_id`、`paper_order_drafts.scan_id`。
- `paper_accounts.id` → `paper_orders.account_id`、`paper_fills.account_id`、`paper_positions.account_id`、草稿 `account_id`。
- `paper_orders.id` → `paper_fills.order_id`。
- 标的和行情通过 `(symbol, market)` 关联。

当前只有各表主键自动创建的唯一索引，没有额外二级索引。行情主键支持按 `(symbol, market)` 查询日期序列；信号结果主键支持按扫描查询；持仓主键支持按账户查询。审计的实体/时间查询、任务时间排序以及按市场查询股票池没有专用索引，大规模数据可能需要扫描或排序；新增索引需先评估真实查询和执行计划，不应将候选索引写成已实现功能。

## 4. 初始化、种子与迁移

先创建 PostgreSQL 用户和应用数据库并配置 `EVOQUANT_DB_URL`，应用启动会自动建表。也可对已创建的数据库手工执行：

```sh
psql "$EVOQUANT_DB_URL" -v ON_ERROR_STOP=1 -f docs/sql/初始化.sql
```

脚本包含完整建表语句和已有两条增量补列，事务执行，可重复运行；不会创建数据库/用户，不会写入策略、股票池、行情或账户。`CREATE TABLE IF NOT EXISTS` 不会修正既有字段的类型和约束。

种子数据由服务按需创建：`SchedulerService` 默认建立 CN（Asia/Shanghai 15:30）和 US（America/New_York 16:30）的启用配置；`RiskService.current()` 首次读取时创建固定 `risk_state` 行，模式 `research-only`、实盘关闭。它们不是 SQL 静态种子，不应手工复制随机 ID。模拟账户按用户请求创建。

现有自动迁移仅为 `bar_sync_jobs` 补充 `scheduled_for` 和 `target_symbols` 两列，默认值分别为 `''` 和 `'[]'`，通过当前 schema 的字段查询判断缺失。旧库补列使用 VARCHAR，新库为 TEXT，在 PostgreSQL 中均为不限长字符串。没有版本化迁移框架、降级脚本或自动 SQLite 数据迁移；历史 scratch 脚本不属于受支持部署流程。

## 5. 测试与数据边界

数据库集成测试必须显式设置 `EVOQUANT_TEST_DB_URL`。测试不自动创建数据库，不默认访问远程地址；每个测试在配置的数据库内创建随机独立 schema，连接限定其 search_path，结束时只删除该 schema。用户需要具备创建 schema 权限。未配置时数据库测试跳过，纯单元测试仍执行；连接或初始化失败直接报错，不吞异常。

批量 K 线任务、行情、信号、策略、模拟账户/成交和风险状态持久化；回测结果、通用 JobQueue 和演化编排结果主要在进程内存，不应假定重启后可恢复。容器部署使用 PostgreSQL 命名卷 `postgres_data`；删除该卷会丢失数据。备份应使用 PostgreSQL 工具，不能复制旧 SQLite 文件作为当前数据库备份。
