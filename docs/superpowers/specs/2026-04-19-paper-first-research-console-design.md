# 模拟盘中心化研究控制台重构设计

日期：2026-04-19  
范围：`src/stock_quantification/web.py`、页面导航、页面信息架构、运行/研究/模拟盘结果流转

## 1. 背景与目标

当前前端以通用 dashboard 方式组织，`Overview / Research Workbench / Results / Local Paper / Logs / Ops / Config` 的结构更接近“工具集合”，不够贴近用户当前最核心的目标：

1. 持续运行策略
2. 持续优化策略
3. 让中美两个模拟盘账户分别跟随各自最优策略
4. 优先服务“账户增值”和“策略切换决策”，而不是服务通用后台管理

当前主要问题：

- 研究工作台把“策略运行”和“因子实验”堆在同一页，面板太窄，指标阅读压缩严重
- 总览、配置、日志、运维等页面占据了过多导航注意力
- 模拟盘页面仍是账户展示页，而不是主流程核心页
- 研究结果虽然已经能沉淀，但和“当前执行策略”“模拟盘切换建议”之间缺少清晰产品心智
- 页面普遍承担多种职责，导致页面过长、焦点分散、复盘效率低

本次重构的目标不是单纯“美化前端”，而是把前端重构成一个围绕模拟盘增值的研究执行控制台。

## 2. 产品原则

本次设计固定采用以下原则，后续同类页面也应延续：

1. 一级页面只服务一个主目标
2. 二级页面继续按“创建 / 历史 / 详情”或“总览 / 明细”拆分
3. 不把表单、历史列表、详情分析堆在同一长页
4. 页面优先回答“接下来怎么做”，而不是展示系统能力
5. 默认关注账户结果与策略质量，而不是后台配置
6. 中美市场使用同一套产品结构，但账户与策略决策相互独立

## 3. 新的信息架构

### 3.1 一级导航

一级导航收敛为 4 个主入口：

1. 模拟盘
2. 策略优化
3. 策略运行
4. 结果中心

以下旧页面不再保留为主导航：

- 总览
- 项目配置
- 任务日志
- 运维中心

处理方式：

- `总览`：取消独立一级入口
- `项目配置`：取消页面化入口；后续如仍需保留，仅作为开发或隐藏入口
- `任务日志`：拆散并并入“策略运行 / 运行历史”和“模拟盘 / 执行时间流”
- `运维中心`：移出主导航，仅保留隐藏入口用于排障

### 3.2 二级导航

#### 模拟盘

- 主页面
- 持仓
- 成交历史

#### 策略优化

- 创建实验
- 实验历史
- 实验详情

#### 策略运行

- 发起运行
- 运行历史
- 运行详情

#### 结果中心

- 冠军策略
- 挑战者池
- 淘汰策略
- 历史归档

## 4. 模拟盘为核心的主流程

新的产品主线如下：

1. 在“策略优化”中持续做因子实验和多策略对决
2. 产出各市场独立的 `冠军 / 挑战者 / 淘汰`
3. 在“模拟盘 / 主页面”中查看当前账户跟随的策略、最近表现和切换建议
4. 采用“冠军 / 挑战者”半自动切换模式，由用户确认是否切换当前执行策略
5. 在“策略运行”中按当前选择的执行策略运行并写入模拟盘
6. 在“模拟盘 / 执行时间流”中复盘每次运行、调仓、切换和告警
7. 在“结果中心”中做长期沉淀和回顾

这条主线强调：

- 研究服务执行
- 执行服务账户增值
- 结果页服务长期比较

## 5. 双市场双账户模型

系统需明确支持两个独立的模拟盘账户：

- `A股模拟盘账户`
- `美股模拟盘账户`

设计要求：

1. 两个账户使用标签页切换查看，不做双列或上下并排
2. 两个账户分别维护自己的当前冠军策略和挑战者池
3. 两个市场的优化、切换、执行和复盘互不污染
4. 模拟盘页默认进入最近使用的市场标签；若无偏好，则默认先显示 A 股

## 6. 页面设计

### 6.1 模拟盘 / 主页面

这是新的首页级核心页面，也是整个系统的首要入口。

页面顶部先做市场标签切换：

- `A股模拟盘`
- `美股模拟盘`

每个标签下的主页面整合三块核心区域：

#### A. 账户总览

只放最关键且适合大数字展示的指标：

- 当前净值
- 累计收益率
- 本周收益
- 当前回撤
- 当前持仓数
- 最近调仓日

这一层的目标是先回答：账户最近到底有没有增值。

#### B. 执行时间流

采用时间倒序列表，不采用宽表格。

时间流条目类型包括：

- 策略运行
- 调仓执行
- 模拟盘记账
- 冠军切换
- 风险告警

每条卡片默认只展示：

- 时间
- 动作类型
- 结论
- 对账户的影响

展开态再展示：

- 推荐标的
- 成交摘要
- 执行偏差
- 调仓前后变化
- 与当前冠军策略的关系

#### C. 当前策略

这一块只服务一个问题：账户当前为什么在按这套策略跑。

展示内容：

- 当前冠军策略
- 生效时间
- 最近评分
- 最近超额收益
- 保留或继续跟随建议
- 当前最强挑战者
- 是否建议切换
- 切换建议理由
- “设为当前执行策略”操作入口

这一页不承担持仓明细和成交流水的全部展示，它只负责总览、执行复盘和当前策略决策。

### 6.2 模拟盘 / 持仓

独立展示当前账户持仓状态，避免在主页面中塞入过长明细表。

内容包括：

- 当前持仓列表
- 权重
- 成本
- 现价
- 未实现盈亏
- 行业暴露
- 集中度提示

默认按权重或市值排序，强调当前风险结构而不是流水。

### 6.3 模拟盘 / 成交历史

独立展示已发生的执行结果。

内容包括：

- 成交时间
- 买卖方向
- 标的
- 成交数量
- 成交价格
- 现金变动
- 来源策略
- 是否为策略切换后的成交

支持按市场、时间范围和策略来源过滤。

### 6.4 策略优化 / 创建实验

这是策略工厂的入口页，只负责发起新实验，不展示长历史。

页面分为两类入口卡：

- 因子实验
- 策略对决

#### 因子实验

支持：

- 选择市场
- 选择因子
- 调整 tilt
- 设定回测区间
- 设定持有周期
- 设定换手上限
- 设定调仓缓冲

#### 策略对决

支持：

- 选择市场
- 选择要参与对比的预设策略集
- 批量运行

页面不放历史列表，只保留必要输入与发起动作。

### 6.5 策略优化 / 实验历史

采用时间流展示每一次实验结果。

每条实验卡展示：

- 实验时间
- 市场
- 实验类型
- 本轮冠军
- 本轮挑战者
- 决策结论
- 关键指标摘要

点击条目后进入“实验详情”。

### 6.6 策略优化 / 实验详情

聚焦一条实验结果，提供完整分析：

- 实验参数
- 最佳策略或最佳因子组合
- 冠军/挑战者/淘汰结论
- 与当前模拟盘冠军的对比
- 是否建议送入挑战者池
- 是否建议接管模拟盘

这一页的产出必须能直接服务“当前策略”页。

### 6.7 策略运行 / 发起运行

只负责发起运行，不承载历史或分析。

支持：

- 选择市场
- 选择目标模拟盘账户
- 选择运行模式
- 选择是否写入模拟盘
- 选择当前执行策略或默认冠军策略

这里的关键变化是：页面要显式说明本次运行将使用哪套策略，而不是默认隐藏在引擎内部。

### 6.8 策略运行 / 运行历史

时间流展示每次运行：

- 运行时间
- 市场
- 账户
- 策略
- 运行模式
- review 结论
- 是否写入模拟盘
- 对账户的影响摘要

### 6.9 策略运行 / 运行详情

展示单次运行的完整信息：

- 推荐标的
- 目标权重
- 建议买卖
- 实际成交或模拟成交
- review 信息
- 运行后账户变化

### 6.10 结果中心

结果中心不再承担日常操作，只做策略沉淀与长期比较。

拆分为：

- `冠军策略`：当前各市场正式冠军
- `挑战者池`：待观察和待切换候选
- `淘汰策略`：历史失败或暂停使用策略
- `历史归档`：所有长期结果的统一档案入口

## 7. 冠军 / 挑战者切换机制

本次设计采用“半自动切换”。

具体规则：

1. 策略优化产出市场内的冠军和挑战者
2. 当前冠军默认继续服务对应模拟盘
3. 当挑战者优于当前冠军时，在“模拟盘 / 当前策略”明确提示
4. 用户手动点击“设为当前执行策略”后完成切换
5. 切换事件写入执行时间流和结果中心

这样既保留了研究驱动，又避免过早自动换仓。

## 8. 数据流设计

### 8.1 研究到执行

`策略优化 / 实验详情`
-> 生成 `冠军 / 挑战者 / 淘汰`
-> 更新市场级当前候选池
-> 在 `模拟盘 / 当前策略` 展示切换建议
-> 用户确认切换
-> `策略运行 / 发起运行` 默认读取新的当前执行策略
-> 运行后写入模拟盘

### 8.2 执行到复盘

`策略运行`
-> 写入模拟盘
-> 更新账户净值、持仓、成交
-> 在 `模拟盘 / 执行时间流` 追加事件
-> 在 `结果中心 / 历史归档` 沉淀结果

### 8.3 运行历史与任务日志的合并方向

原来的通用任务日志不再独立作为面向用户的主页面。

用户视角下的可见结果应拆入：

- 策略运行 / 运行历史
- 模拟盘 / 执行时间流

系统级异常和运维日志仅保留隐藏入口，不进入主流程。

## 9. 视觉与交互原则

本次重构的交互目标不是“页面更多”，而是“页面更短、更专注、更能做决策”。

### 9.1 布局原则

- 一级页不做超长混合页
- 二级页默认单一职责
- 主页面优先卡片+时间流
- 明细页优先表格+筛选
- 详情页优先摘要+分段分析

### 9.2 阅读优先级

默认优先级固定为：

1. 账户结果
2. 当前策略
3. 切换建议
4. 最近执行
5. 明细查询

### 9.3 风格要求

- 保持现有深色控制台风格，但减少“后台管理感”
- 增强账户与策略指标的视觉层级
- 避免面板并排过多导致信息压缩
- 让时间流成为主要复盘方式，而不是过多密集表格

## 10. 迁移策略

### 10.1 第一阶段：信息架构调整

- 收缩一级导航
- 新增二级导航
- 拆出模拟盘主页面、持仓、成交历史
- 拆出策略优化和策略运行的创建/历史/详情页

### 10.2 第二阶段：数据挂接

- 当前冠军/挑战者状态挂接到模拟盘
- 运行历史和实验历史分别接入时间流
- 让运行页显式选择或展示本次执行策略

### 10.3 第三阶段：冠军切换闭环

- 增加市场级当前执行策略状态
- 在模拟盘页支持手动确认切换
- 把切换事件写入执行时间流和结果中心

## 11. 错误处理与边界情况

### 11.1 无实验结果

- “当前策略”页不显示伪结论
- 明确提示尚未产生冠军策略
- 提供跳转到“策略优化 / 创建实验”

### 11.2 无运行历史

- 时间流显示空状态
- 提供跳转到“策略运行 / 发起运行”

### 11.3 无成交或空仓

- 持仓页与成交页分别显示空状态
- 不回退成泛化说明文字堆叠

### 11.4 中美账户配置不完整

- 某一市场缺少账户时，只影响对应标签
- 不阻塞另一市场正常使用

### 11.5 挑战者优于冠军但未切换

- 当前策略页保留醒目提示
- 不自动切换
- 执行页默认继续沿用当前冠军，直到用户确认变更

## 12. 测试策略

需要覆盖以下测试方向：

1. 一级导航与二级导航渲染
2. 旧页面入口移除后路由 fallback 行为
3. 模拟盘主页面正确整合账户总览、执行时间流、当前策略
4. 持仓页与成交页的独立渲染
5. 策略优化和策略运行的创建/历史/详情拆分
6. 时间流链接到详情页的跳转
7. 冠军/挑战者状态在模拟盘页的展示逻辑
8. 空状态和缺失数据场景

## 13. 预期收益

重构完成后，前端应达到以下结果：

1. 用户打开系统后首先看到的是账户增值情况，而不是后台管理入口
2. 用户能清楚知道当前中美两个模拟盘各自跟随哪套策略
3. 用户能持续查看每一次实验、每一次运行、每一次切换
4. 页面长度和职责明显收敛，减少“长 dashboard”带来的认知疲劳
5. 整个前端从“功能控制台”变成“围绕模拟盘增值的研究执行台”
